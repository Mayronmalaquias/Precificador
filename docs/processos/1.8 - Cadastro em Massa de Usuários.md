# 1.8 — Cadastro em Massa de Usuários (corretores)

> 🆕 Complementa [[1.3 - Cadastro de Usuários]] (cadastro unitário pelo RH) com a **carga em lote**
> a partir da base de corretores. Repo **`Estudos`**, `Script/cadastrar_usuarios_corretores.py`.

## 1. Objetivo
Gerar usuários do sistema da Inteligência a partir de um CSV de corretores e, opcionalmente,
cadastrá-los na API via `POST {base_url}/auth/cadastro`.

## 2. Regras de Negócio
- **Colunas de entrada:** `Nome`, `IdCorretor`, `IdGerente` (aceita variações de caixa/underscore).
  Linha sem uma das três é **descartada**.
- **Mapeamento:** `IdCorretor` → `id_usuarios`; `IdGerente` → **`team`** (o time do usuário é o
  gerente).
- **`username`** = nome com espaços trocados por `_`. Em caso de **colisão**, todos os homônimos
  recebem sufixo `_{id_usuarios}`.
- 🔴 **`password` fixa `"12345678"`** para todo mundo.
- **`permissao` fixa `"user"`**; `email`, `telefone`, `instagram`, `descricao` saem **vazios**.
- Sempre grava o CSV de saída (`usuarios_corretores_para_cadastro.csv` por padrão), mesmo quando
  também envia para a API.
- **Envio:** sequencial, um `POST` por usuário, `Content-Type: application/json`, timeout 120s
  e pausa de 0,2s entre chamadas. **Sem retry** — falha é só contabilizada e logada.
- **Não é idempotente:** rodar duas vezes tenta cadastrar tudo de novo (o resultado depende de como
  a API trata usuário duplicado).

## 3. Fluxo
```bash
# só gerar o CSV, sem tocar na API
python Script/cadastrar_usuarios_corretores.py --input Dim_Corretor.csv --somente-gerar-csv

# gerar e cadastrar
python Script/cadastrar_usuarios_corretores.py --input Dim_Corretor.csv --base-url http://localhost:5000
```
1. Lê o CSV e monta o DataFrame de usuários.
2. Resolve colisões de `username`.
3. Salva o CSV de saída.
4. Se não for `--somente-gerar-csv`, faz os `POST` e imprime o resumo `Sucessos / Falhas`.

## 4. Troubleshooting
| Sintoma | Causa provável (código) | Ação |
|---|---|---|
| `Não encontrei nenhuma das colunas esperadas` | CSV sem `Nome`/`IdCorretor`/`IdGerente` | Exportar a `Dim_Corretor` completa |
| Menos usuários que corretores | `dropna` nas 3 colunas obrigatórias | Preencher `IdGerente` dos corretores sem gerente |
| `[TIMEOUT]` | API lenta (timeout 120s) | Subir `--timeout` ou rodar em lotes menores |
| `[ERRO] status=4xx` | Usuário já existe / payload rejeitado | Ver a resposta impressa; conferir duplicidade |
| Usuário duplicado após rerodar | Script não é idempotente | Rodar só com os novos |
| `username` com sufixo numérico | Homônimos no CSV | Comportamento esperado |

**Riscos/lacunas:**
- 🔴 **Senha padrão `12345678` para todos** — sem troca obrigatória no primeiro acesso.
  Some-se a isso o achado de **API sem autenticação** registrado em [[2.9 - Gestão de Segredos]]:
  qualquer um que alcance a rota pode cadastrar usuários.
- ⚠️ `--base-url` default `http://localhost:5000` — apontar para produção sem querer (ou não apontar) é fácil.
- ⚠️ Sem retry e sem relatório persistido de falhas (só console).
