# 3.5 — ETL / Unificação de Vendas

> Histórico e taxas de resolução em [[MAPA_BANCO]].

## 1. Objetivo
Ter uma base **única e contínua de vendas 2015→hoje**, sem duplicar, com pessoas resolvidas para
`id_usuarios` (FK) — servindo rankings, dashboards e comissão.

## 2. Regras de Negócio
- **`contratos` = base única** (coluna `fonte`: `planilha` | `legado_pre2024`). Planilha `Vendas`
  cobre 2024+; `importar_contratos_legado.py` trouxe 895 vendas pré-2024.
- **`vendas`** = camada canônica (view/tabela) lida de `contratos`; `*_id` com **FK → usuarios**;
  `*_nome` preservado para linha histórica não-casável.
- **Resolução de pessoa:** nome/código → `id_usuarios` via `pessoa_alias` ([[3.3 - Auditoria e Qualidade de Dados]]).
- **Sync:** `sync_contratos` (Sheet→DB, upsert por `id_contrato`, não apaga sumidos —
  ver [[2.6 - Sincronização com Planilhas]]); marca `fonte='planilha'`, ignora legado no "removidos".
- **`popula_vendas.py`** re-executável (`INSERT...SELECT`, recarrega `vendas`).

## 3. Fluxo
1. Planilha `Vendas` (2024+) → `sync_contratos` → `contratos`.
2. Legado pré-2024 já importado em `contratos` (`fonte=legado_pre2024`).
3. `popula_vendas.py` / refresh → `vendas` (canônica, pessoas resolvidas).
4. Rankings/dashboards leem a base resultante.

## 4. Troubleshooting
| Sintoma | Causa | Ação |
|---|---|---|
| Venda duplicada | contratos×vendas_legado sobrepostos | `vendas` dedup por `id_contrato`; ver `vw_vendas` |
| Pessoa não resolvida | Nome fora do de-para | `pessoa_alias` (origem manual) |
| Histórico 2015–2023 sumindo | Só existia em `vendas_legado` | Confirmar import em `contratos` |
