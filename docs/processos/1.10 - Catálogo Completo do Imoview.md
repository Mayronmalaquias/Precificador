# 1.10 — Catálogo Completo do Imoview

> Substitui na prática o export manual descrito em [[1.7 - Preparação de Estoque (Imoview)]].
> Aquele documento continua valendo como registro do processo antigo — e da planilha, que
> ainda é a origem de 3.022 linhas históricas de `fato_estoque`.

## 1. Objetivo

Ter no banco **todo** o estoque do Imoview, não só o que está vago/disponível, com o
captador e o percentual de comissão que o CRM registra.

Mudou o que a operação consegue perguntar. Antes o catálogo local tinha 2.624 imóveis —
21% do que o Imoview mostra. Hoje tem **12.451**.

## 2. A descoberta que destravou tudo

Havia uma crença registrada de que a API do Imoview não devolvia o captador, e por isso o
`fato_estoque` dependia de planilha exportada à mão.

**Ela devolve.** Falta enviar **`exibircaptadores=true`** em `/Imovel/RetornarImoveis`.

> ⚠️ Eu mesmo cheguei a confirmar a crença errada nesta sessão: testei o endpoint, recebi
> `[]` em `captadores` e concluí que o dado não existia. O que existia era um parâmetro
> que eu não estava mandando. A documentação do endpoint, colada pelo usuário, resolveu.
> **Lição:** campo vazio numa API com dezenas de flags opcionais é hipótese sobre a
> requisição, não conclusão sobre o dado.

Com a flag, a cobertura de captador foi de 53% para **96% (11.951 de 12.451)**. E vem
junto o `percentual` de cada captador — o rateio oficial do CRM, que **não é sempre
50/50**.

## 3. Parâmetros que a API exige

| Parâmetro | Valor | Por quê |
|---|---|---|
| `naoconsiderarmeusite` | `True` | Sem ele a API devolve só os 741 imóveis do site próprio |
| `exibircaptadores` | `true` | Sem ele `captadores` vem `[]` — ver acima |
| `numeroregistros` | 20 (máximo) | Teto da API; 12.451 imóveis = ~625 páginas |
| `situacao` | 0 = todas, 6 = Desativado | Desativado é 80% do catálogo (9.991) |

## 4. Como rodar

```bash
python sync_areas_imoview.py            # rotina diária: situações ativas
python sync_areas_imoview.py --tudo     # catálogo inteiro, inclui Desativado
python sync_portais_imoview.py          # publicação nos portais (venda/disponível)
python sync_portais_imoview.py --tudo   # portais do catálogo inteiro
python completar_fato_estoque.py            # SIMULA, não grava
python completar_fato_estoque.py --gravar   # grava
```

`MAX_PAGINAS_TUDO = 700` a 20 registros por página cobre 14.000 imóveis — folga sobre os
12.451 atuais. Se o catálogo passar disso, a varredura para silenciosamente no teto.

## 5. O 401 que mente

A API responde **`401 "Chave inválida!"`** sob rajada. Não é a chave: na primeira vez que
aconteceu (página ~180 de uma varredura de 625) a mesma chave funcionou no segundo
seguinte.

Por isso `_pedir()` tem retentativa com backoff exponencial (5s, 10s, 20s, 40s) e
`PAUSA_ENTRE_PAGINAS = 0.35`.

> ⚠️ **Custo do desenho antigo:** `coletar()` só grava no fim da varredura. Quando o 401
> derrubou a rodada na página 180, as 179 páginas anteriores foram perdidas. O sync de
> portais já nasceu com **commit por lote** justamente por isso. `sync_areas_imoview`
> ainda não — é a melhoria óbvia se a varredura completa virar rotina.

## 6. Publicação nos portais

`POST /Imovel/RetornarPortaisImoveis` aceita **200 códigos por chamada** e devolve, por
imóvel, a lista de portais com situação, tipo de destaque e dias de publicação.

Guardado como **agregado** em `imovel_area` (migration `20260827_area_portais`), não uma
linha por portal: a pergunta da tela é "quantos estão publicados e com que destaque".
Uma tabela `imovel_portal` seria mais fiel e é o caminho se alguém precisar de "quantos
anúncios no OLX especificamente".

`destaque_portal` guarda o **maior nível ativo**. Imóvel Simples em quatro portais e Super
Destaque num quinto está, na prática, em Super Destaque — é por ele que a operação paga.

Portal **retirado não conta**: só entram os de `codigosituacao = 1`.

Medido em 28/08/2026, sobre os 999 de venda/disponível:

|---|---:|
| Publicados em algum portal | 651 |
| Simples | 412 |
| Destaque | 133 |
| Super destaque | 106 |
| **Não publicados** | **348** |

> 📌 **348 imóveis à venda, disponíveis, fora de todo portal.** Não é bug de código — é

## 7. Completar o `fato_estoque`

`fato_estoque` sempre foi alimentado por upload de planilha (`origem='upload'`), só com
Vago/Disponível, três levas em 2026 (26/06, 24/07, 03/08). Vendido, Desativado, Em
moderação e Em reforma nunca entraram.

`completar_fato_estoque.py` insere o que existe no catálogo e não existe lá. Rodou duas
vezes: **1.546** linhas e depois **9.797**. Estado atual:

| | |
|---|---:|
| Linhas totais | 14.365 |
| Códigos distintos | 12.450 |
| `origem='imoview_api'` | 11.343 |
| `origem='upload'` (histórico) | 3.022 |
| Catálogo sem linha na fato | **1** |

**O que ele não faz:** não reescreve nem apaga linha existente. Cada leva antiga é um
snapshot datado; reescrevê-la apagaria o histórico de quem cuidava do imóvel antes. Também
não mexe em imóvel que já tem linha, mesmo com captador diferente — decidir qual fonte
vence (planilha ou API) é uma decisão de negócio que ainda não foi tomada.

**Por que inserir com a data de hoje é seguro:** os três consumidores
(`ranking_service._responsavel_no_estoque`, `leads_service._estoque_por_codigo`,
`imovel_rel_service`) deduplicam por código pegando `data_estoque` mais recente. Nenhum
agrega uma leva inteira, então leva parcial não distorce contagem.

## 8. O resolvedor de nomes

O catálogo devolve o nome **completo** ("IONNARA VIEIRA DE ARAÚJO"); o cadastro tem o
curto ("Ionnara Vieira"). Casar por igualdade perdia captações de gente ativa.

E-mail seria a chave certa, mas só **17 dos 92 usuários ativos** têm um preenchido.

Regra em `ranking_service._resolver_captador`: normaliza sem acento, tenta igualdade,
depois **prefixo por tokens com no mínimo dois tokens** — um token só ("Patrícia") casaria
pessoas diferentes. Entre homônimos, **o ativo vence**: o cadastro tem a mesma pessoa em
contas antigas desativadas, e creditar na conta morta a tira da equipe.

> ⚠️ Dois bugs que essa função teve, ambos corrigidos, ambos silenciosos:
> 1. **Espaço duplo** — "RODRIGO  PAVONI" (145 imóveis) não casava com "RODRIGO PAVONI".
>    Corrigido com `" ".join(limpo.split())`.
> 2. **Range vazio** — `range(len(tokens)-1, 1, -1)` não executa nenhuma vez para nome de
>    2 tokens, que é a maioria do cadastro.
>
> Juntos: 1.053 → **1.318** captadores resolvidos.
