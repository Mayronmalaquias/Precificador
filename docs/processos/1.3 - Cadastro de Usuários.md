# 1.3 — Cadastro / Manutenção de Usuários (RH)

## 1. Objetivo
Manter o cadastro de usuários que sustenta **hierarquia de permissões**, **controle de
corretores por time**, **relatórios** e **controle de RH**.
- **Quem gerencia:** equipe da **Inteligência** (administrador) e os **assistentes**, pela aplicação web.
- **Ciclo de vida:** usuário existe enquanto um **gerente o mantém**; se para de desempenhar
  ou não alinha com as políticas, o gerente **solicita à Inteligência o desligamento**.
- **Liberação de login:** **não existe mais** — o usuário nasce `ativo=true`. O RH atua só no
  desligamento. Não há tela pública de "criar conta": só quem já está logado cadastra.

## 2. Regras de Negócio
- **Campos obrigatórios:** `nome`, `id_usuarios` (`C61xxx`), `team` (`G61xxx`),
  `permissao`/tipo (**corretor · gerente · diretor · administrativo**).
- **`id_usuarios`:** digitado **manualmente**; **único** no banco (`uq_usuarios_id_usuarios`).
- **`id_imoview`:** campo **"Código Imoview"** no formulário de cadastro (origem: aba
  "Corretores" do xlsx do AppSheet — `Corretor` + `Código Imoview`). **Único** — cadastro com
  código já usado devolve **409**. Sem ele o corretor **não aparece** no seletor do
  [[1.9 - Lançamento de Imóvel pelos Assistentes|Lançar Imóvel]].
- **Poderes por permissão:**
  - **Diretor / Administrativo (e administrador):** editam usuários, veem relatórios de **toda a
    empresa**, **desativam** / retiram acesso. Cadastram qualquer permissão.
  - **Assistente:** cadastra usuário novo (só **corretor / gerente / assistente** — não cria
    administrativo, administrador nem diretor).
  - **Gerente:** mantém os corretores do próprio time; preenche RH dos corretores ativos da equipe.
  - **Corretor:** acesso base.
- **Desativar** (soft) ≠ **Excluir** (delete físico) — ver Fluxo.

## 3. Fluxo
1. **Cadastro** — Inteligência ou assistente preenche os campos manualmente (`id_usuarios` é
   gerado automático: próximo `C61xxx`). *Implementação:* usuário nasce `ativo=true`,
   `status="Ativo"`, `desligado=false` → **já loga**.
2. ~~Liberação (RH)~~ — **removida**. `alterar-ativo` continua existindo só p/ desativar/reativar.
3. **Edição** — diretor/administrativo/administrador editam geral (`editar-usuario`);
   gerente preenche RH dos ativos do time (`editar-rh-gerente`); troca de time = `alterar-gerente`
   (muda o `team` para o do novo gerente).
4. **Desligamento** — gerente solicita → Inteligência desativa. *Implementação:*
   `alterar-ativo(false)` → `ativo=false` + `desligado=true` + `status="Inativo"`; usuário
   **permanece arquivado** (preserva histórico/relatórios). **Excluir** (`excluir-usuario`) =
   **delete físico**, uso de exceção.

## 4. Troubleshooting
| Sintoma | Causa | Situação / Ação |
|---|---|---|
| Não loga ("aguardando validação") | Usuário foi **desativado** | Cadastro novo já nasce ativo; ver `alterar-ativo` |
| Cadastro devolve 409 no Imoview | Código já é de outro corretor | Conferir a aba "Corretores" do xlsx / `usuarios.id_imoview` |
| Corretor não aparece no Lançar Imóvel | `id_imoview` vazio | Preencher via `editar-usuario` |
| `id_usuarios` duplicado | Código repetido | Sem colisão até hoje (campo único) |
| Desligado aparece no ranking | — | Nunca precisou; desativar já tira do ranking |
| Troca de gerente | `alterar-gerente` | Muda o nome do time para o do novo gerente |
| Exclusão por engano | delete físico | Puxar backup do banco (sem reversão automática) |

**Lacunas/riscos:** usuários **antigos** ainda podem estar sem `id_imoview` (só os do xlsx foram
semeados) → de-para manual no [[1.2 - Importação de planilhas de base|1.2]]; sem fila do RH, o
controle de quem entra é só a permissão de quem cadastra; exclusão física só reverte via backup.
