# 1.9 — Lançamento de Imóvel pelos Assistentes

> Antes o assistente lançava **duas vezes**: na planilha do AppSheet (que gerava o cartão no
> Trello via `trelo.gs`) **e** manualmente no Imoview. Agora é **um lançamento só** na página
> `/LancarImovel`, que dispara Imoview + estoque + Trello.

## 1. O que faz (1 lançamento → 3 destinos)
Página **`/LancarImovel`** (menu "Lançar Imóvel") → `POST /api/v1/assistente/incluir-imovel` →
1. **Imoview** (`/Imovel/IncluirImovel`) — cadastra o imóvel no CRM, retorna o **código**.
2. **Estoque** — anexa uma linha na planilha Google **"Estoque - Geral" › aba "Planilha - Geral"**
   (ID `1869RJIoK064xnXjMHDXP0tNan5bkbJPZa-_jVfwY1cY`), nas 32 colunas do cabeçalho.
3. **Trello** — cria o cartão no board de estoque (porta o `trelo.gs`): nome = endereço,
   campos personalizados (código/matrícula/IPTU/corretor/assistente), label de cessão.

Estoque e Trello são **não-fatais**: se falharem, o imóvel já entrou no Imoview e o front avisa.

**Classificação de foco (grava no banco):** no lançamento o sistema classifica o foco pela
regra do Bases (`classificar_foco`): **FOCO PP** (bairro Plano Piloto/Asa/etc. + valor ≥ R$1M),
**FOCO AC** (Águas Claras + valor ≥ R$600k), ambos exigindo comissão ≥ 3,5% e imóvel
**residencial** (pela destinação do Imoview: 1/3). Grava `foco_pp/foco_ac` em **`imovel_legado`**
(keyado pelo código do Imoview) + preenche a coluna **Foco** da planilha. **Sem isso o imóvel
apareceria como "NÃO LOCALIZADO"** na classificação de foco do ranking (que lê `imovel_legado`).
Só vale p/ lançamentos novos — imóveis antigos "não localizado" precisam de import/backfill.
Código: `lancamento_service._persistir_foco`.

> ⚠️ Dois "focos" distintos: (1) `imovel_legado.foco_pp/foco_ac` — regra PP/AC, é o da
> classificação; (2) `vendas_legado.foco` (histórico) — usado no relatório VGC+foco
> ([[2.2 - Rankings]]). Não confundir.

## 2. Acesso (permissão `assistente`)
- Nova permissão **`assistente`** (`AuthContext.isAssistente`, guarda `AssistenteRoute`; admin/diretor
  também acessam). Menu "Lançar Imóvel" só p/ assistente + administrador.
- **Menu enxuto p/ o assistente (2026-08):** quem é `assistente` (e não admin) vê **só "Lançar
  Imóvel"** no header — o dropdown **Serviços** é filtrado p/ só esse item, a **barra de atalhos**
  (Parcerias/Portal/61Financeiro/Experts) e o menu **Gestão** ficam ocultos. Gate em `Header.js`
  via `!isAssistente` nas listas `atalhos`/`servicos`/`gestao` (Lançar Imóvel escapa do filtro).
  Admin/diretor inalterados. É restrição **de menu** — não troca as guardas de rota.
- **Usuários** criados via `backend/seed_assistentes.py`: username **`nome_sobrenome`** com
  **underscore** (ex. `lucas_oliveira`, `victor_hugo`; nome simples → só o primeiro), senha
  **`61Imoveis`**, `ativo`. 14 criados; idempotente (pula existentes).
- **Login:** o assistente digita o **nome natural** ("Lucas Oliveira") — o `normalizar_user` do
  login faz `espaço→underscore` + minúsculo + sem acento → bate no username. ⚠️ **Underscore, não
  ponto:** username com `.` não casa (a normalização usa `_`) — foi o bug do login dos estagiários.
- ⚠️ **Hash de senha `pbkdf2:sha256`:** o seed (e todo cadastro/edição) grava com
  `method="pbkdf2:sha256"`. Se gravar com o default do Werkzeug novo (**scrypt**), a VM
  (`Werkzeug==2.0.3`) estoura no login (`unsupported hash type scrypt`). Detalhe e correção em
  [[3.8 - Deploy e Produção]].

## 3. Formulário (subconjunto da planilha + obrigatórios do Imoview)
Corretor (→ `codigousuario`), Finalidade/Destinação/Tipo/Unidade/Local-chave (dropdowns do
Imoview), endereço, valores/áreas, características, **proprietário (obrigatório)**, matrícula/IPTU
(Trello), descrição, fotos. Dropdowns vêm de `GET /assistente/imoview/listas`.

**Corretor → codigousuario:** usa `usuarios.id_imoview`. Populado de `backend/seed_id_imoview.py`
(aba "Corretores" do xlsx; código **1 é placeholder** e é ignorado). ~109 corretores mapeados.

## 4. Regras do Imoview (aprendidas no teste — imóvel 12367)
- **Códigos são INT** (usuario/unidade/finalidade/destinação/tipo/localchave). String → `null-reference` (HTTP 500).
- **Proprietário é obrigatório** (nome + CPF **válido** + telefone). Sem ele → `null-reference`.
- `parametros` vai como **JSON na query**; fotos em multipart no campo `fotos`.
- Valores de referência: **unidade `61 IMOVEIS` = 7610**; finalidade 1=Aluguel / 2=Venda; localchave 6=Corretor.
