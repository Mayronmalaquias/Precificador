# 2.9 — Gestão de Segredos / Credenciais

## 1. Objetivo
Guardar e controlar acesso às credenciais (senha RDS, ids de planilha, chave Anthropic, Imoview,
service account/OAuth do Google).

- **Onde:** `.env` (back + `aplicativo/`) + JSONs em `app/utils/asserts/`.
- **Acesso:** setor de **Inteligência**.
- **Git:** **fora do versionamento** — verificado: só `.env.example` versionado; `.env` reais e
  `service_account.json` são git-ignored. ✅ Sem cofre (é `.env` + arquivo).

## 2. Regras de Negócio
- **Rotação:** chaves **nunca trocadas**.
- **Backup dos segredos:** só no **HD interno da empresa** (cópia única).
- **Produção:** `.env` nas VMs de back e front (quem tem SSH lê).
- **JSONs:** copiados manualmente (fora do git).
- **API sem chave:** hoje a API **não exige autenticação** do app mobile (planejado adicionar).

## 3. Fluxo
1. **Credencial nova/alterada:** atualizar nas **VMs** (back/front) **e no local**.
2. **JSONs** (`service_account`, `token.json`): copiar o arquivo **via SSH**.
3. **Backup:** atualizar a cópia no **HD interno**.
4. **Acesso:** setor de Inteligência (SSH nas VMs).

## 4. Troubleshooting
| Sintoma | Situação atual |
|---|---|
| HD interno corrompe (cópia única) | Nunca corrompeu; sem redundância declarada |
| Indisponibilidade | Setor de Inteligência no geral ajusta (não é 1 pessoa) |
| Vazamento de chave | Sem medidas — atualizar tudo manualmente |
| API sem chave (mobile) | Hoje qualquer um chama; chaves virão no futuro |

**Riscos/lacunas (segurança):** chaves **nunca rotacionadas** · backup em **cópia única** ·
**sem plano de resposta a vazamento** · **API pública sem autenticação** (até virem as chaves) · sem cofre.

## Perguntas em aberto / melhoria 🙋
1. **Adicionar autenticação na API** (a mais urgente — hoje é aberta ao mobile/qualquer chamada).
2. **Backup redundante** dos segredos (além do HD interno — ex. cofre/gerenciador criptografado).
3. **Rotação** mínima das chaves críticas (RDS, Anthropic, Imoview) + plano de resposta a vazamento.
4. Avaliar **AWS Secrets Manager**/Vault no lugar de `.env` em produção.
