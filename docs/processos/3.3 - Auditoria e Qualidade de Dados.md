# 3.3 — Auditoria e Qualidade de Dados

> Detalhe completo em [[MAPA_BANCO]] (esta nota é o resumo operacional).

## 1. Objetivo
Garantir **identidade canônica** de pessoas/equipes e detectar duplicados, nomes soltos e
referências órfãs — para os relatórios/rankings baterem.

## 2. Regras de Negócio
- **Chave de pessoa:** `usuarios.id_usuarios` (`C61xxx`), único (`uq_usuarios_id_usuarios`).
- **De-para:** `pessoa_alias` (`alias_key` → `id_usuarios`, `origem`) resolve nome/código sujos.
- **Views de auditoria** (`sql/`): `vw_usuarios_duplicados` (códigos repetidos),
  `vw_pessoa_nao_resolvida` (refs sem id + sugestão), `vw_vendas` (leitura unificada).
- **Dedup:** `dedup_usuarios.sql` (com backup `usuarios_dup_backup` antes de mexer).
- **Problema recorrente:** Imoview não sincroniza IDs → nomes precisam de de-para
  (mesma dor do [[1.2 - Importação de planilhas de base]] e do `id_imoview` vazio no [[1.3 - Cadastro de Usuários]]).

## 3. Fluxo
1. Ao importar dados, nomes que não casam vão para `vw_pessoa_nao_resolvida`.
2. Resolver com `INSERT INTO pessoa_alias (... origem='manual')`.
3. Duplicados de código → analisar `vw_usuarios_duplicados` → dedup (com backup).

## 4. Troubleshooting
| Sintoma | Causa | Ação |
|---|---|---|
| Corretor "sumiu" do relatório | Nome não resolvido p/ id | Adicionar alias em `pessoa_alias` |
| Venda contada 2x | Duplicidade contratos×legado | Ver `vw_vendas` / [[3.5 - ETL de Vendas]] |
| Código de pessoa repetido | Colisão (ex. ADM001/ADM002) | `vw_usuarios_duplicados` + dedup |
