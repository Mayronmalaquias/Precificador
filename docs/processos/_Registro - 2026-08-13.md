## 4. Bugs encontrados e corrigidos

### 4.1 Na base / integrações

| Achado | Impacto | Correção |
|---|---|---|
| **O `quantidade` da API do Imoview mente** — declara 853 disponíveis, a varredura acha 1.051 | painel subnotificava ~200 imóveis (**-19%**) | total passou a ser contado do catálogo |
| **Leads do C2S parados em 07/08** | corretor não achava lead recente | importação manual de 08 a 13/08 (**370 leads**) |
| **`visitas.tipo_captacao` não diz quem captou** — 53% de acerto | corretor via botão de relatório de imóvel alheio, e não via do dele | regra passou para a **API do Imoview** (`codigocaptador`) |
| **`fato_captacao.codigo_imovel` formatado** (`"10.258"`) | cruzamento por código falhava | normalização no consumo (origem continua errada) |

### 4.2 Que eu mesmo introduzi

Registrados por honestidade — os três passaram despercebidos até serem apontados:

1. **Rota duplicada quebrou o download do gerente.** Criei `/imoveis/pdf/download` sobre uma
   rota que já existia em outro módulo; a nova venceu o registro e o gerente passou a receber
   `400` em vez do PDF. Corrigido: relatório único, com a restrição virando parâmetro
   opcional. ([[1.4 - Relatório de Visita]])
2. **Botão "Trocar senha" sem estilo.** Escopar o `button {}` vazado (conserto correto)
   derrubou os botões que dependiam do vazamento. Corrigido com uma base neutra em
   `design-system.css`. ([[2.16 - Consulta de Imóveis]] §10.1)
3. **Baseline que nunca saía do baseline.** A detecção era "tabela de eventos vazia", e o
   baseline não escreve nada — toda execução seria baseline e nenhum evento sairia jamais.
   Corrigido com uma linha-marco. ([[2.14 - Visão do Diretor]])

### 4.3 De escopo (quem vê o quê)

| Achado | Correção |
|---|---|
| Seletores de corretor do funil e do estoque listavam **as 7 equipes** para o gerente | `Usuarios.team.in_(equipes do escopo)` |
| Abas de Propostas/Leads ignoravam o gerente escolhido no dropdown | passam `team`/`id_gerente`; **não burlável** por quem não é global |
| Auditoria por equipe escondia equipe sem movimento | todas as equipes do escopo entram, zeradas |
| Auditoria com `limit(500)` — julho teve **494 visitas** | teto para 5.000 |

## 5. Deploy

Ordem sugerida. Nada disso está na VM ainda.

```bash
# back
cd /home/ubuntu/Precificador && git pull origin dev_miron
cd backend && venv/bin/python -m alembic -c migrations/alembic.ini upgrade head
sudo systemctl restart precificador

# front
cd /home/ubuntu/Precificador && git pull origin dev_miron
cd frontend && npm run build && sudo cp -r build/* /var/www/html/
```

**Crons que continuam faltando** (ver [[3.8 - Deploy e Produção]]) — são a causa de dois dos
bugs de hoje:

```cron
10 3 * * *  cd /home/ubuntu/Precificador/backend && venv/bin/python importar_leads_c2s.py >> ~/leads_c2s.log 2>&1
30 4 * * *  cd /home/ubuntu/Precificador/backend && venv/bin/python sync_areas_imoview.py >> ~/areas_imoview.log 2>&1
```

⚠️ A varredura do Imoview passou de ~4 min para **~11 min**. Se colocar timeout no job, use
20 min ou mais.

⚠️ `.env` da VM precisa de `CONTACT2SALE_TOKEN` — sem ele o lançamento de lead responde 503.

## 6. Em aberto

1. **O POST de criação de lead no C2S nunca foi disparado.** Criar um lead de teste geraria
   registro real, distribuído a um corretor, e a API não documenta remoção. As validações
   (permissão, telefone/e-mail, canal) foram testadas — rodam antes da chamada externa. **O
   primeiro lançamento real é o teste.**
2. **"Propostas por venda" ainda não é confiável** — Propostas Efetivas entrou em agosto e as
   vendas vêm de `contratos`, com histórico completo. Deu 0,9 proposta por venda, o que é
   impossível. Só vale quando o registro estiver em uso por todas as equipes.
3. **Imóvel desativado tem data aproximada.** Situação 6 (9.312 imóveis) não é varrida —
   custaria ~466 páginas/dia. O desativado é deduzido por ausência e recebe a data da
   detecção, não a real.
4. **Recorte por equipe só enxerga imóvel com captação registrada** (825 de 1.052
   disponíveis). A soma dos recortes não fecha com o total da empresa, e não deve mesmo.
5. **1 proposta com `team` nulo** — só a diretoria a vê. Buraco de cadastro, vale conferir.
6. **`Parceiro` (G61004) é gerente com `team` vazio** — cai no escopo de "vê só o próprio".
   Funciona por acidente; outro gerente sem `team` veria menos do que deveria.
7. **Importador de contratos continua gravando `codigo_imovel` formatado.** Corrigir na
   origem e remover as normalizações espalhadas pelo consumo.
