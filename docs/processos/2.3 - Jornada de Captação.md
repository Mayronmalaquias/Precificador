# 2.3 — Jornada de Captação

> ⚠️ **Rascunho automático** inferido de `back-end/app/services/captacao_service.py` e do
> model `captacao`. Validar regras operacionais (ver "Perguntas em aberto").

## 1. Objetivo
Acompanhar o imóvel que o corretor está tentando captar, por **etapas**, com histórico de
cada ação — do primeiro contato até a captação (ou fechamento/perda). É a carteira ativa do
corretor dentro do sistema. Front: `JornadaCaptacao` (`/JornadaCaptacao`, `?novo=1` cria).

## 2. Regras de Negócio
- **Etapas (ordem):** `escolha → prospeccao → interacao → apresentacao → captacao`.
- **Status:** `ativo` · `exclusividade` · `fechado` · `captado` (deriva das ações).
- **Dono:** cada captação tem `id_corretor` + `nome_corretor` + `team` (carteira do corretor).
- **Histórico automático:** toda mudança relevante (avanço/retorno de etapa, ação registrada,
  ação realizada, objeção, book enviado, dado do proprietário, captação, fechamento,
  exclusividade) gera 1 linha em `captacao_historico` (etapa, tipo, descrição, data).
- **Avanço vs retorno:** ao trocar `etapa_atual`, o sistema compara a ordem e registra
  "Avançou para X" ou "Voltou para X"; atualiza `data_entrada_etapa`.
- **Exclusividade:** marca `status=exclusividade` + `exclusividade_ate` (data).
- **Fechamento:** `status=fechado` + `motivo_fechamento` + `data_fechamento`.
- **Reatribuição de carteira:** trocar `id_corretor`/`nome_corretor` move os imóveis entre
  corretores (ver [[3.9 - Reatribuição de carteira]] — ex.: Marcio→Lucas).

## 3. Fluxo
1. **Criar** (`POST /captacoes`) — corretor lança o imóvel; nasce em `escolha`; grava histórico
   "Imóvel lançado na jornada". Se já entra em `prospeccao`, registra o avanço.
2. **Atualizar** (`PUT /captacoes/<id>`) — a cada ação/campo alterado, gera as linhas de
   histórico correspondentes e aplica os campos da etapa.
3. **Consultar** — `GET /captacoes` (por corretor) · `GET /captacoes/<id>` ·
   `GET /captacoes/<id>/historico`.
4. **Exclusividade** (`POST /captacoes/<id>/exclusividade`).
5. **Fechar** (`POST /captacoes/<id>/fechar`, com motivo).
6. **Excluir** (`DELETE /captacoes/<id>/excluir`) — apaga a captação **e** seu histórico (delete físico).
7. Alimenta o **snapshot diário** ([[2.4 - Snapshot e Evolução de Captação]]) e os dashboards do gerente.

## 4. Troubleshooting
| Sintoma | Causa provável (código) | Ação |
|---|---|---|
| Ação não apareceu no histórico | Valor igual ao atual (só registra em mudança) | Conferir se o campo mudou de fato |
| Etapa "voltou" inesperada | `etapa_atual` setada p/ etapa anterior | Ver ordem escolha→…→captacao |
| Captação sumiu | `DELETE /excluir` = delete físico (apaga histórico junto) | Restaurar via backup do banco |
| Imóvel no corretor errado | `id_corretor`/`nome_corretor` incorretos | Reatribuir (ver [[3.9 - Reatribuição de carteira]]) |

## Atualizações (2026-07-31)

- **Escopo por `team`**: o gerente vê as captações e a lista de corretores da equipe dele (`team`), não pelo id. Ver [[2.1 - Dashboards do Gerente]].
- **Captações seguem o corretor**: ao mudar o corretor de equipe (`alterar_gerente`), o `team` gravado nas captações dele é atualizado para a equipe nova — o gerente novo passa a ver os **processos antigos** (feitos antes de o corretor entrar), pois são do corretor. Backfill único de dados existentes: `UPDATE captacao c SET team = u.team FROM usuarios u WHERE c.id_corretor = u.id_usuarios AND c.team IS DISTINCT FROM u.team`.
- **Novos filtros** (topbar do Kanban, combinam em AND):
  - **Corretor** — dropdown (todos os corretores da equipe, filtra por `id_corretor`). Diretor: respeita a equipe selecionada.
  - **Bairro** — dropdown **normalizado**: agrupa grafias equivalentes (minúscula, sem acento, espaços colapsados) numa opção só (ex.: "Águas Claras / AGUAS CLARAS / aguas claras" → 1). Não mescla palavras diferentes ("Águas Claras Norte" fica separado).
  - **Book enviado** (sim/não), **Ação** (pendente/feita), **Parados** (+7/+14/+30 dias na etapa, `data_entrada_etapa`), **Endereço** (busca).
  - **Equipe** (diretor) usa a lista mestra da tabela `equipes` (mostra equipes novas sem captação).

### Atualização 2026-08-21 — responsáveis com outro papel

O filtro de corretor combina os corretores ativos do cadastro com os responsáveis que aparecem
nas captações carregadas. Isso cobre usuários que possuem carteira própria na Jornada, mas cuja
permissão atual é outra — como Fernando Borges (`C61134`), cadastrado como gerente da Alpha.
Essa complementação vale somente para o **filtro**: o modal de nova captação continua oferecendo
apenas usuários ativos com permissão `corretor`, evitando ampliar a regra de atribuição.
