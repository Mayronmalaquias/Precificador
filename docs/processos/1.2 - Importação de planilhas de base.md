# 1.2 — Importação de Planilhas de Base (BI)

## 1. Objetivo
Alimentar o **BI (Power BI)** com o estoque de imóveis da 61 vindo do **CRM Imoview**.
Baixa 3 exports do Imoview, trata com scripts Python e carrega na planilha Base Inteligência,
que é a fonte do Power BI.

> **Antes:** dados carregados em planilhas Google Sheets (estado atual).
> **Evolução (to-be):** substituir a carga manual pelos endpoints
> `POST /api/v1/admin/bases/importar/{captacao,saida,estoque,destaque}` → tabelas
> `fato_captacao/fato_saida/fato_estoque` no banco. O site **já aceita** as bases e os
> relatórios saem bem, mas **ainda não foi liberado**. Ver [[MAPA_BANCO]] (fato_*).

## 2. Regras de Negócio
- **Fonte:** CRM **Imoview** (da Universal). 3 exports `.xls` (HTML disfarçado) / `.csv`.
- **Chave do imóvel:** `Código` do imóvel — amarra estoque/captação/saída. **Sempre presente.**
- **Janela:** semanal, **sexta a quinta**.
- **Mapeamento das 3 bases:**
  | Export Imoview | Vira | Regra |
  |---|---|---|
  | Todos disponíveis (todos os tempos) | **Estoque** | snapshot do estoque atual |
  | Disponíveis cadastrados sex→qui | **Captação** | novos da semana |
  | Situação alterada sex→qui | **Saída** | tudo que **não** é `Vago/Disponível` = saída |
- **De-para corretor (nome → IdCorretor):** Imoview não sincroniza IDs com a base `usuarios`.
  O nome do captador é convertido via aba `Dim_Corretor`; quando não bate, é resolvido
  **manualmente** (olha o nome no CRM e insere o IdCorretor + código do diretor à mão).
  Mesma dor resolvida no banco por [[MAPA_BANCO|pessoa_alias]].
- **Classificação Foco (em `registrarCaptacao.py`):**
  - **Foco PP:** bairro ∈ {Plano Piloto, Asa Sul, Asa Norte, Noroeste, Sudoeste, Jardim Botânico,
    Lago Norte, Lago Sul, Setor Sudoeste} **e** valor ≥ R$ 1.000.000 **e** comissão ≥ 3,5% **e** residencial.
  - **Foco AC:** bairro Águas Claras **e** valor ≥ R$ 600.000 **e** comissão ≥ 3,5% **e** residencial.
  - Residencial = tipo fora de {T7..T11}.
- **Deduplicação:** captação por `Código+DataEntrada+Captador1`; saída por `Código+DataSaida`.

## 3. Fluxo
Exports Imoview (semanal, sexta→quinta):
- **Estoque:** todos os disponíveis de todos os tempos.
- **Captação:** disponíveis cadastrados de sexta passada até quinta.
- **Saída:** todos que mudaram de situação de sexta até quinta.

Tratamento (scripts na mesma pasta; credenciais em `../cred.json`; planilha
`1HQDdcbUMj276hnIbPs-WwdWHiUPzMhPRWt4HHRyYGnw`):
1. `legado/Bases/tratamento_estoque.py` — lê `.xls` via `pd.read_html` (lxml), pega a maior
   tabela, quebra `Captadores` por `|` em Captador1..3 → gera `Fato_Estoque_IMPORTAR.xlsx`
   (`Codigo, Captador1..3, Gerente, DataEstoque`).
2. `legado/Bases/registrarCaptacao.py` — filtra `Finalidade=Venda`; mapeia bairro/tipo→id
   (cria bairro novo se faltar); nome do captador→IdCorretor via `Dim_Corretor`; classifica
   Foco PP/AC; upsert `Dim_Imovel` + append `Fato_Captacao`.
3. `legado/Bases/registrarSaida.py` — regra: não-`Vago/Disponível` = saída; resolve
   captador/gerente pelo registro mais recente em `Fato_Captacao`; append `Fato_Saida`.
   > Dependência técnica: **captação roda antes da saída** (saída lê `Fato_Captacao`).
4. **Power BI** recarrega. **Fonte atual do BI = a planilha (Sheets)**, abas `Fato_*`/`Dim_*`.

## 4. Troubleshooting
| Sintoma | Causa | Situação / Ação |
|---|---|---|
| Captador não bate | Imoview não sincroniza IDs com `usuarios` | Manual: nome no CRM → insere IdCorretor + código do diretor |
| Código ausente | — | Nunca ocorre (sempre tem código) |
| Script quebra no export | Coluna faltando / acento | Nunca quebrou até hoje |
| Tipo não mapeado | Tipo novo | Sem problema até hoje |
| Registro errado / duplicado | Execução indevida | Apaga o registro manual + verifica a base |

Lacunas: de-para nome→corretor manual; sem log de execução; correção = deleção manual.
