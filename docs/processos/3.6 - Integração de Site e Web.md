# 3.6 — Integração de Site e Web (Fullstack)

> Detalhe em `front-end/README.md` e `back-end/README.md`.

## 1. Objetivo
Servir o site público (precificador, leads, chat) e a plataforma interna (visitas, captação,
dashboards, RH, vendas) integrando SPA React ↔ API Flask.

## 2. Regras de Negócio
- **Front:** React 19 + react-router-dom 7; auth client-side (`AuthContext` + `localStorage`);
  guardas de rota (`PrivateRoute`/`AdminRoute`/`AdministradorRoute`) — ver [[3.7 - Permissionamento]].
- **API base:** `src/services/api.js` normaliza `REACT_APP_API_URL` para terminar em `/api/v1`
  (default relativo = mesma origem atrás de proxy).
- **Back:** Flask-RESTx, 18 namespaces sob `/api/v1`, Swagger em `/docs`. CORS por `CORS_ORIGINS`.
- **Rotas públicas** (`/`, `/Experts`, `/61Financiamento`, `/verificarImovel`…) vs **privadas**
  (mapa de rotas no README do front).

## 3. Fluxo
1. Navegador carrega a SPA (estáticos servidos por `serve`/proxy).
2. Componentes chamam `api.get/post/...` → `/api/v1/...`.
3. API roteia namespace → service → banco.
4. Deploy: back via systemd `precificador`; front build estático (mesma origem).

## 4. Troubleshooting
| Sintoma | Causa | Ação |
|---|---|---|
| CORS bloqueado | Origem fora de `CORS_ORIGINS` | Adicionar origem no `.env` do back |
| Front chama API errada | `REACT_APP_API_URL` incorreta | Ajustar env do build |
| 404 em rota SPA no refresh | Proxy sem fallback p/ index.html | Configurar reverse proxy |
